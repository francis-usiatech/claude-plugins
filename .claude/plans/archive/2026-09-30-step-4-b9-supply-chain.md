## Design decisions (resolve the spec's deferred open questions)
- D1 Advisory source: npm bulk advisory endpoint `POST https://registry.npmjs.org/-/npm/v1/security/advisories/bulk` (keyless, the source `npm audit` uses; returns `critical|high|moderate|low` directly). Probed 2026-09-29: 200 in ~90 ms.
- D2 Registry data: full packument `GET https://registry.npmjs.org/<name>` (scoped names URL-encoded) for `deprecated`, `time[dist-tags.latest]` and `versions[v].scripts`. The abbreviated document is not used: its `modified` is not the last release date (probe: `request` shows 2026, last release 2020).
- D3 Typosquat: a bundled list of ~200 popular npm names kept in the shared module; an added unscoped name ≥ 5 characters at optimal-string-alignment distance 1 from a list name (and not itself on the list) is high risk. Covers `expresss` (insertion) and `lodahs` (transposition).
- D4 Versions looked up: the exact version from a lockfile in the same change; otherwise the base version of a manifest range (`^1.2.3` → 1.2.3); `*`, `latest` and similar use `dist-tags.latest`.
- D5 Budget and scope: advisories are looked up for every added or changed entry (manifest and lockfile) in one bulk POST. Registry lookups (R4, R5) run only for direct dependencies added in a manifest, at most 8 at a time. Guard lookups share one 6 s deadline (hook timeout is 10 s); the deadline is injectable so tests stay fast. CI uses 20 s per request. Offline findings are computed first, so a timeout still returns them. Uses `AbortController` and timers only (no `AbortSignal.any`, for Node 20.0 support).
- D6 Guard: `evaluate()` becomes async; lookups are injected (`opts.lookups`) so unit tests never touch the network. A failed or timed-out lookup logs one `fail-open` entry naming the lookup (R13, A11).
- D7 CI testability (pre-flight FLAG 1, decided by Francis): the CI check logic moves into an exported function that takes the lookups as a parameter; `governance-checks.mjs` stays a thin entry point that wires the real lookups. There is no env-var or fixture seam in the shipped script. The parity test calls the exported function with stub lookups (and still runs the entry point for the offline B10 fixtures).
- D8 Dependency paths: `package.json`, `package-lock.json`, `pnpm-lock.yaml`, `yarn.lock` (any directory, excluding `node_modules/`). Lockfile parsing is line/JSON based, no YAML library (package-lock v1–v3, pnpm v6/v9 keys, yarn classic and berry).
- D9 Non-registry specifiers and 404s (pre-flight FLAG 2, decided by Francis): `workspace:`, `file:`, `link:`, git/GitHub/URL specifiers and `npm:` aliases skip lookups and give an `sc-non-registry` warning. A registry 404 for a plain name gives an `sc-not-found` warning (possible dependency confusion), not a lookup failure. ADR 0001 records that package names and versions are sent to registry.npmjs.org.

## Commands and actions
- The normal gate (`npm test`, `claude plugin validate`). No dependency adds.
- Network: the shipped guard and CI checks call the two public npm endpoints (D1, D2), sending package names and versions to registry.npmjs.org. Tests never call the network (injected stub lookups).
- After merge, each confirmed with Francis at the time: push tag `v0.8.0`; refresh the installed plugin (`claude plugin marketplace update usiatech`, `claude plugin update usiatech-engineering@usiatech`).
- ADR 0001 starts the `docs/adr/` convention with status Proposed until Francis accepts it.

## Out of scope
- Ecosystems other than npm, pnpm and yarn; `npm-shrinkwrap.json`; `bun.lockb`
- Auto-fixing dependencies; auditing dependencies the change didn't touch; transitive dependency advisories beyond the entries a lockfile change adds or changes
- The B10 follow-up hardening in #13
